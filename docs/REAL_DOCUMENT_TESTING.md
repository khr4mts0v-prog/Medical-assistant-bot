# Проверка на реальных медицинских документах

Цель — проверить не только распознавание типа, но и безопасное поведение всей загрузки. Этот протокол не заменяет клиническую валидацию и не предполагает отправку документов внешнему ИИ.

## Подготовка набора

1. Использовать отдельный тестовый семейный архив и отдельную папку на Яндекс Диске.
2. Начать с 10–20 документов разных видов: лабораторные анализы, заключения УЗИ/КТ/МРТ, выписки, назначения, направления, справки и многостраничные документы.
3. Включать разные источники: цифровые PDF, сканы, фотографии с телефона, повёрнутые страницы, слабый контраст, несколько документов в одном PDF.
4. Использовать только документы, на обработку которых есть право. По возможности скрыть не относящиеся к проверке персональные сведения. Не загружать реальные документы в публичные issue/PR.
5. До загрузки вручную записать эталонные значения: пациент, тип, дата самого документа, число страниц и ожидаемое имя файла.

## Матрица тестов

Для каждого файла записывать:
- верно ли определён пациент;
- верно ли определён основной тип документа;
- верно ли извлечена дата документа (не дата рождения и не дата исследования, если документ выдан позже);
- сохранились ли оригинал и OCR;
- можно ли найти документ по пациенту, типу, дате и ключевому слову;
- запросил ли бот уточнение при неоднозначности;
- не создался ли дубль при повторной отправке.

Дополнительно выполнить негативные сценарии:
- документ с ФИО двух членов семьи;
- документ без ФИО и без явной даты;
- нечитаемый/пустой скан;
- повторная загрузка одного файла;
- отправка двух документов подряд, когда первый ожидает уточнения;
- прерывание процесса после помещения файла в очередь и восстановление через `/retry_save`;
- временная недоступность Яндекс Диска;
- пользователь без доступа к семейному архиву пытается продолжить ожидающую загрузку.

## Критерии допуска

- **Ноль ошибочных назначений пациента** на тестовом наборе. Если есть сомнение, бот обязан запросить подтверждение.
- Даты и типы оцениваются отдельно; сомнительные значения должны переводиться в уточнение, а не молча приниматься.
- Повторная загрузка не создаёт второй индексный документ.
- Оригинал и OCR согласованы с записью в SQLite; сбой не оставляет документ в состоянии, которое нельзя восстановить.
- Документы и токены одной семьи не видны другой семье.
- Любая ошибка сохранения даёт понятный способ повтора или безопасной отмены.

## Важно

Не отправлять OCR-текст или документы в Hugging Face/другой внешний сервис без отдельного осознанного согласия. Для первой проверки классификации ИИ не нужен. Реальные результаты следует считать внутренней проверкой качества, а не медицинским заключением.
