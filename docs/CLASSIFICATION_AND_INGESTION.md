# Классификация и загрузка документов

## 1. Поток загрузки

```text
Telegram photo/PDF
    ↓
проверка формата и размера
    ↓
шифрованный временный оригинал + зашифрованный sidecar
    ↓
OCR (русский + английский)
    ↓
классификатор документа ─── дата итогового документа
    ↓                              ↓
реестр пациентов ← сопоставление ФИО/инициалов
    ↓
проверка обязательных полей: пациент → дата → тип
    ↓
при недостатке данных — вопрос пользователю, файл не теряется
    ↓
имя + папка короткого пациента
    ↓
оригинал + OCR-текст + индекс SQLite + история
    ↓
удаление зашифрованной временной загрузки
```

Неуверенный результат не должен превращаться в уверенную автоматическую сортировку. Тип автоматически принимается только при `confidence == high`; иначе интерфейс предлагает категорию и конкретный тип. Пациент выбирается только при уникальном совпадении. Если есть несколько имён в документе, родственник/врач не должен автоматически становиться пациентом.

## 2. Иерархия типов

Конечные названия классов оставлены стабильными для совместимости с API и тестами. Категория — дополнительная навигационная метка, не замена конечному классу.

| Верхний уровень | Конечные типы |
|---|---|
| Клинические записи и выписки | выписной эпикриз; выписка из медицинской карты; история развития ребёнка; контрольная карта диспансерного наблюдения; протокол осмотра или приёма; медицинская карта или наблюдение |
| Лабораторная диагностика | лабораторный отчёт |
| Инструментальная диагностика | заключение УЗИ; заключение ЭКГ; рентгенологическое заключение; заключение КТ; заключение МРТ; эндоскопическое заключение |
| Патоморфология и операции | патоморфологическое заключение; операционный протокол |
| Консультации, назначения и направления | консультация специалиста; назначение или рецепт; направление |
| Профилактика и реабилитация | вакцинальный документ; санаторно-курортная документация |
| Справки и административные документы | медицинская справка; справка о временной нетрудоспособности |
| Беременность, рождение и смерть | документ по беременности и родам; медицинское свидетельство о рождении; медицинское свидетельство о смерти |

В `AIAnalise.py` правила заголовков/номеров форм имеют больший вес, чем обычные слова в теле. Отдельно проверяются отрицательные признаки: «результат не приложен», историческое упоминание исследования, рекомендации пройти исследование, список назначенных обследований. Каждый PDF-страничный сегмент классифицируется отдельно; метки страниц сохраняются в анализе. Файлы с несколькими разными документами не нарезаются автоматически на самостоятельные документы в этой версии.

## 3. Дата документа

Порядок:

1. Явные метки даты итогового документа: «Дата заключения», «Дата оформления», «Дата выдачи», «Заключение от», «Протокол от».
2. Явная универсальная метка «Дата:».
3. Единственная оставшаяся дата, если она не находится в контексте даты исследования/рождения/забора материала и т. п.

Если после фильтрации остаётся несколько возможных дат с одинаковым приоритетом — дата считается неопределённой и запрашивается у пользователя. Дата исследования храниться как найденный факт может в OCR, но не подменяет дату документа в имени файла. Ручной ввод принимается в обычных форматах дат и нормализуется в `ДД-ММ-ГГГГ`.

Имя файла:

```text
ДД-ММ-ГГГГ <Краткое название> — <8 символов хеша оригинала>.<ext>
```

Пример: `12-05-2026 УЗИ малого таза — 8a7f12de.pdf`.

## 4. Реестр пациентов и алиасы

- `patients.name` — короткая метка папки, например `Олег` или `Маша`.
- Полные ФИО и варианты написания хранятся в зашифрованном поле `aliases_enc`; не включаются в имена папок или файлов.
- При добавлении пациента пользователь задаёт короткую метку, затем может указать варианты через `;`: полное ФИО, ФИ, фамилию с двумя инициалами, фамилию с инициалом.
- Из полного имени автоматически выводятся типовые сокращения: фамилия + имя, фамилия + инициалы, фамилия + первый инициал, имя + фамилия. Это помогает при форматировании вроде `Иванов И.П.` или `Иванов И.`, но неоднозначное совпадение приводит к уточнению.
- Одно слово вроде «Маша» совпадает только в поле пациента или отдельной строкой в верхней части документа. Врач, родитель и представитель не должны подменять пациента.
- Алиасы могут совпасть у нескольких членов семьи; в таком случае система не выбирает наиболее удобное имя наугад.

## 5. Отложенная загрузка

Оригинал временно сохраняется зашифрованным в каталоге рядом с базой `archive.sqlite3`; sidecar с OCR, семейным ID, контрольной суммой и текущим шагом диалога тоже зашифрован Fernet. Права файлов ограничиваются на уровне ОС. После ответа пользователя состояние сохраняется, затем система продолжает с недостающего поля. После успешного сохранения или отмены временные файлы удаляются.

Поддерживаются `/cancel` для очистки очереди и `/retry_save` для повторной попытки, если Яндекс Диск был временно недоступен. Состояние очереди и текущий вопрос восстанавливаются после перезапуска процесса. Переходы не требуют повторной отправки исходного файла.

## 6. Как оценивается классификатор

Регрессионные тесты покрывают ожидаемый класс, отрицательные упоминания, OCR-пробелы, смешанные страницы, неоднозначные даты и варианты ФИО. `tests/evaluate_classification_corpus.py` считает accuracy на выбранном корпусе, Precision/Recall/F1 по каждому классу, confusion pairs и долю abstention («не определено»).

Это тестовый корпус из публичных пустых форм и синтетических примеров; он не представляет распределение реальных заполненных документов. Совпадение со 100% выбранных примеров не является оценкой клинической/производственной точности. Следующий этап повышения качества — собирать деидентифицированные случаи с реальными ошибками OCR, назначать эталонные классы вручную и разбирать confusion pairs перед изменением правил.
